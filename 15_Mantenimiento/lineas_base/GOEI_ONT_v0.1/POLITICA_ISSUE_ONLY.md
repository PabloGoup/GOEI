# Política Issue-Only para la Ontología GOEI

**Ámbito:** GOEI Ontology Baseline v0.1 y todas sus versiones sucesoras.

No se acepta ningún cambio ontológico sin Issue formal previo. El Issue debe contener:

- ID y título inequívoco;
- elemento y versión afectados;
- problema observado;
- clasificación: editorial, técnico, semántico o científico;
- evidencia y decisión de origen, si aplica;
- impacto sobre entidades, relaciones, axiomas, datos, documentos y software;
- compatibilidad y migración;
- autoridad requerida;
- criterio verificable de cierre.

Flujo mínimo:

`Abierto → Clasificado → Analizado → Decisión requerida/adoptada → Cambio propuesto → Verificado → Nueva baseline → Cerrado`

Los cambios editoriales también requieren Issue para preservar el checksum y la cadena de custodia. Los cambios científicos exigen una decisión del Comité Científico; los cambios puramente técnicos no pueden alterar la semántica aprobada.
